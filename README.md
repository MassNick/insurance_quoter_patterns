# Auto insurance quoting agent on Azure AI Foundry

Status: **design only.** Nothing is deployed. The demos simulate agent behaviour and make no Azure calls.
Started: 2026-11-24. Starting point: the user's draft `DGAG architecture.drawio.xml`. This folder refines that draft; it does not replace it.

A customer gets an auto insurance quote by chatting with an advisor agent. The agent asks in chat first and opens small forms it generates on the fly (A2UI) only when they help; it can also read the customer's documents to pre-fill. A memory agent pulls facts and signals out of every message. The BFF holds the state, asks the customer to double-confirm sensitive changes, runs end-of-form rules after every change, hands the file to an advisor when a rule stops the online quote, and logs everything. The client demo UI is for Desjardins Assurances, French first (D12).

## Key design decisions

| # | Decision | Why |
|---|---|---|
| D1 | **One hosted agent container (`quote-agent`)** in Foundry Agent Service. It runs Python on Microsoft Agent Framework and contains two `Agent`s: the main quoter and the memory agent. | Required: exactly 1 hosted container. Both agents share the session, history and tools with no extra network hop. Foundry hosted agents are GA. |
| D2 | **Invocations protocol** between the BFF and the hosted agent, streamed over SSE, using the custom event envelope in `contracts/events.md`. | A turn carries more than text in both directions: state, form submits and confirmations go in; A2UI, state deltas, signals and suggestions come out. Invocations agents can still be evaluation targets. |
| D3 | **Exactly 2 model calls per turn as the norm.** The memory and main agents run concurrently. Terminal tools (A2UI, lookups, suggestions, phase) end the main agent's loop through function middleware. Button-driven actions (Get my quote, adjust offer) run the quote tool **before** the main call, so the agent narrates the result in that single call. | Meets the 2-call rule and keeps time to first token low. The exception is a narrate tool started from free text (for example "what if I raise my deductible?" or a coverage question), which costs one extra completion. It is counted, and the SLO is at least 85% of turns at exactly 2 calls. **To confirm with the user:** see open question Q1. |
| D4 | **The BFF is the only writer of session state.** The memory agent proposes changes. The BFF merges them using source precedence, deterministic-field rules and derived fields, then writes Cosmos DB and its own per-session cache. | One audited place for state, so the models cannot write state directly. |
| D5 | **A2UI 1.0 over MCP** (the current stable spec; v0.9.1 is closed). The agent sends an intent-level **FormSpec**. The A2UI MCP server compiles it, using the state catalog, into one `createSurface` that carries the components and the data model, with `@path` bindings and `@checks`. It returns as an MCP embedded resource of type `application/a2ui+json` marked for the user only, and the hosted agent forwards it to the BFF out of band. Field lookups (address, year/make/model, VIN, document reads) come back from the renderer as `callAgentFunction` and are answered by the BFF with no model call. | Keeps model output small and the UI always valid. Form fields bind to state JSON Pointers, so the BFF can push memory-agent deltas into an open form as `updateDataModel` (live autofill). |
| D6 | **Toolbox `auto-quoting-toolbox`** puts the two MCP servers (Azure Container Apps) behind one MCP endpoint with agent-identity auth. **Foundry IQ** is a knowledge base over Blob Storage indexed by Azure AI Search, reached through its MCP endpoint (`knowledge_base_retrieve`). | Hosted agents reach platform tools through a toolbox MCP endpoint. Foundry IQ gives grounded, cited coverage explanations. |
| D7 | **The document agent is a separate Foundry prompt agent on `gpt-5.6-luna`** (vision, structured output). Only the BFF calls it, when a file is uploaded. | Keeps the 2-call turn intact. Untrusted document content stays behind a structured boundary, which defends against prompt injection. |
| D8 | **Deterministic fields** are `contact_consent`, `has_claims`, `has_convictions_in_past_three_years`, `was_denied_or_cancelled` and `driver_license_number`. Each is flagged `deterministic: true` in `contracts/state-catalog.json` and goes through a BFF-enforced double confirmation. | The model can propose these changes but cannot commit them. |
| D9 | **Prompt caching by layout.** The static prefix comes first, then the append-only history, then volatile state. `prompt_cache_key` is set per agent, prompt version and session. | Lowers cost and latency (see `prompts/token-budget.md`). The static prefix is about 4k tokens against the 30k cap. |
| D10 | **OpenTelemetry end to end.** Agent Framework GenAI spans, the Foundry tracing view, and Application Insights or Log Analytics, with W3C `traceparent` propagated from the frontend through the BFF, the hosted agent, the toolbox and MCP. | One trace per turn shows both model calls, every tool call and every A2UI message. |
| D11 | **Canada regions** (Canada Central primary, Canada East for disaster recovery). | Quebec Law 25 and data-residency expectations. Hosted agents are available in both regions. |
| D12 | **Client demo UI for Desjardins Assurances: Variation C, "Assistant plein écran".** Dark-green header with a "Conversation \| Formulaire complet" toggle and a "Parler à un conseiller" button. Step chips: Documents, Vous, Véhicules, Conducteurs, Antécédents, Soumission. A left rail on desktop that becomes a bottom tab bar on phones. A collapsed "Votre dossier" side panel (States and Quotes tabs) that opens only on click, with a spring and then staggered items. Plain French field labels with hover help, from new `label_fr` and `help_fr` in the state catalog. A mini Desjardins-style hexagon bot avatar with eyes. The ball-to-form animation is kept. The customer UI is French first (fr-CA); the developer trace stays in English. At 600 px wide or less, the form covers the conversation while the suggestions and the composer stay usable, and panels become sheets. **The official Desjardins logo must replace the placeholder mark before any external showing.** | The client chose C from three variations. A full-screen conversation keeps one task in focus, and the collapsed panel keeps the file visible without crowding a phone. The current mark is a hand-drawn approximation, not a brand asset. |
| D13 | **Text-first gathering.** The main agent asks in chat by default. It opens a small subject form (one subject, about 5 fields at most: Vous, Véhicule, Conducteurs, Antécédents) only when a subject has several structured fields or the customer asks for forms. Right after the intent is identified and consent is confirmed, it offers once to read documents (driver's licence, registration certificate, current insurance policy) to pre-fill. Without documents, it gathers through a mix of chat and subject forms. | Long forms read like a paper application. Short questions keep the conversation the main channel, small forms handle clusters of structured fields, and documents remove most typing. |
| D14 | **Answer-mode preference.** The agent never asks the customer to choose between text and forms. It says once that they can answer by text or ask for forms. The memory agent captures a stated preference as `session_preferences.answer_mode` (`text`, `forms` or null) in its structured output. The BFF stores it in the session document, and the main agent follows it: `text` means no forms except the driver-vehicle board, `forms` means subject forms. | An up-front choice is a question most people cannot answer yet. Reading the preference from what they say costs no extra model call. |
| D15 | **Generic suggested replies.** Items from `ui.suggest_replies` fit any customer at that step: never personal data, names, emails, vehicle models or values the customer has not given. At most 4 items, at most 40 characters each. The BFF validates them and drops non-compliant items (PII patterns, proper names, long text). They render as bubbles above the composer. | A suggestion that guesses a name or a car puts words in the customer's mouth and can leak data. The BFF filter backs up the prompt rule deterministically. |
| D16 | **Reopenable form chips.** Every A2UI surface leaves a chip in the transcript (`Formulaire : <titre>`) with state `open`, `submitted`, `closed` or `sent`. Clicking a submitted or closed chip sends `ui.surface_reopen`, and the BFF renders the same FormSpec again through the A2UI MCP server, prefilled from the current committed state, in edit mode. No model call, no new turn. Saving goes through the normal BFF commit and the rule check, and appends a system note to the history so the next turn knows. | Customers fix an answer where they gave it. Reusing the stored FormSpec keeps the form identical and costs nothing. |
| D17 | **AssignmentBoard replaces the matrix** for driver-vehicle assignment (insurance catalog component, widget `assignment_board`). The customer drags people from a pool onto vehicle cards, each with one "Conducteur principal" slot (exactly 1) and a "Conducteurs occasionnels" slot (0 or more). Tap and keyboard alternatives exist, and the page scrolls automatically while dragging on a phone. It writes `/household/driver_vehicle_assignments` (role `principal` or `occasional`) and checks `onePrincipalPerVehicle`. | A drivers-by-vehicles grid is hard to read on a phone and allows invalid combinations. The board makes the one-principal rule visible. |
| D18 | **DocumentDrop** (insurance catalog component, widget `document_drop`): tiles for the driver's licence, the registration certificate and the current policy. Each upload goes from the BFF to the document agent (`gpt-5.6-luna`). The extracted fields are shown with their confidence, and the customer reviews and edits them before they are committed with `source=document`. | One place for the documents offered in D13. Review before commit keeps a model's reading out of state until a person has checked it. |
| D19 | **End-of-form rules in the BFF.** `EndOfFormRules` (`bff/rules/end_of_form.py`) runs synchronously after every state commit, whatever the source (memory-agent deltas, form submits, document reviews, full-form saves, confirmations), once per commit batch, before the main agent runs. `STOP` ends the online quote; `FLAG` adds an advisor signal and the journey continues. A STOP on values only inferred from chat asks one confirmation question first. On STOP the BFF closes the open surfaces and renders the end-of-form surface: reason, rule id, an editable short summary of the conversation, contact fields and consent to transmit. Sending it creates an advisor hand-off with a reference such as `CNS-123456` that carries the summary. Example rules: `VEHICULE_EXOTIQUE`, `VEHICULE_MODIFIE_PERFORMANCE`, `USAGE_AGRICOLE` and `REFUS_OU_RESILIATION` (STOP); `JEUNE_CONDUCTEUR_PRINCIPAL` (FLAG). New SSE events: `rules.hit` and `handoff.created`. | Recommended over a callback on the memory agent's response, because forms, documents and full-form edits never pass through the memory agent. The commit is the single choke point that every source passes through. The check is deterministic, auditable and costs no model call. |
| D20 | **Full-form mode.** The header toggle shows the whole quote as one long form, prefilled with everything known (chat, documents, forms) and grouped by catalog entity. Saving commits with `source=form` and runs the rule check. Switching back returns to the conversation. | Some customers want to see and fix everything at once. It reuses the catalog, the compiler and the commit path, with no model call. |

## Open questions (assumptions used until answered)

- **Q1: what does "2 model calls per user response" mean?** It can mean two LLM agents per turn, or two completions per turn. This design treats it as two completions and enforces it with terminal tools and pre-executed button actions. A free-text request that needs a quote or a knowledge-base answer narrated costs 3. If the rule is a hard cap, those cases would show the result first and narrate it on the next turn.
- **Q2: which model deployments?** `gpt-5.6-luna` for documents is given. The main and memory agents are placeholders (`MAIN_MODEL_DEPLOYMENT`, `MEMORY_MODEL_DEPLOYMENT`): a GPT-5.6-family deployment for the main agent and a small, fast one for memory. Availability of each in Canada regions is **not verified**; a Data Zone or Global deployment may be needed. **Decision (2026-11-25): left open on purpose. The model deployments and their regions stay a decision for the team; the solution takes them as Terraform variables and agent settings.** **Answered for the first dev deploy (2026-11-25):** the GPT-5.6 family in `solution/settings.yaml` (main `gpt-5.6-terra`, memory and documents `gpt-5.6-luna`, embeddings `text-embedding-3-large`), Global Standard, the only option for these models in Canada Central; a Law 25 review comes before real customer data.
- **Q3: is the quote engine an existing rating API?** The `quoting` MCP server is assumed to wrap one. The demo uses a fake rating formula.
- **Q4: authentication for customers.** The design assumes an anonymous session that can later sign in with Microsoft Entra External ID (a CIAM tenant).
- **Q5: is the A2UI MCP server's custom catalog acceptable?** It adds YMM picker, VIN field, address lookup, repeater, AssignmentBoard (D17), DocumentDrop (D18) and offer cards on top of the A2UI 1.0 basic catalog components, plus insurance check functions, and the React renderer must implement them. Whether the chosen React/web renderer supports 1.0 yet is unverified: Google's 1.0 announcement says some renderers are still on 0.9.1.
- **Q6: French labels and help.** The catalog declares `en` and `fr`, and every field now has `label_fr` and `help_fr`, with `enum_fr` for enum options (D12). Someone at the client must sign off the French wording before NFR-I18N-1 can pass.
- **Q7: where do advisor hand-offs go?** Assumption: the BFF writes each hand-off (reference, reason, rule id, summary, contact details, consent timestamp) to a Cosmos `handoffs` container, and the advisor system (CRM or work queue) reads it from there. The integration, and any call-back delay promised to the customer, are to be confirmed. **Decision (2026-11-25): leave the hand-off unconnected. The BFF writes hand-offs to Cosmos `handoffs` only; no advisor connector is built.**
- **Q8: who owns the end-of-form rules?** Assumption: underwriting owns the rule list and its thresholds (the exotic make list, the under-25 limit for a young principal driver), and the BFF holds them in code with tests (`bff/rules/end_of_form.py`). A change goes through the normal release with the golden-set evaluation.

## How to open the demos

Open `demo/journey.html`, `demo/form-gallery.html` or `demo/ui-variations.html` directly in a browser. There is no server or network, and no keys. The pages are built from `demo/src/` by `python3 demo/build.py`.
